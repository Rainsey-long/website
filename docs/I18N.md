# English and Khmer — how the site is bilingual

Read this before touching any visible text. Mechanism: `lib/i18n.ts` (header comment).

## URLs

- English at the root (`/sky`), Khmer under `/km` (`/km/sky`). `proxy.ts` rewrites `/km/x` to `/x` and passes the language in a header; one page component serves both.
- Never build a second route tree. Never redirect by browser language.
- `/api`, `/og`, `/admin` and `.ics` files have no Khmer twin.

## In code

| Need | Use |
|---|---|
| Language in a server component / `generateMetadata` | `const lang = await getLang()` from `@/lib/langServer` |
| Language in a client component | `const lang = useLang()` from `@/components/client/LangProvider` |
| Strings | `const T = defineMessages({ en: {...}, km: {...} })` from `@/lib/i18n`, at the top of the file that uses them; then `T[lang].key`. Functions are allowed for strings with values: `count: (n: number) => \`${n} days\`` / `(n: number) => \`${khmerDigits(n)} ថ្ងៃ\`` |
| Links | `import Link from "@/components/client/LocaleLink"` (never `next/link`). Hrefs stay English paths ("/sky"); the wrapper adds `/km` |
| `router.push`, `redirect`, any URL you build | `localePath(path, lang)` / `useLocalePath()` |
| Metadata | `export async function generateMetadata() { const lang = await getLang(); return pageMetadata({ lang, title: T[lang].title, description: T[lang].description, path: "/sky" }); }` — `path` is always the English path |
| Breadcrumb names | pass the page-language name; `Breadcrumbs` handles "Home" |
| Dates | `longDate(key, lang)`, `fullDate(key, lang)`, `monthName(m, lang)`, `monthYear(y, m, lang)` (lib/dates.ts); `timeIn/dateTimeIn/shortDateIn(…, lang)` (lib/format.ts) |
| Numbers shown in Khmer text | `num(n, lang)` → Khmer digits on Khmer pages (`khmerDigits`) |
| Sign / animal / element / planet names | `signName(slug, lang)`, `animalName(slug, lang)`, `yearOf(slug, lang)`, `elementName(e, lang)`, `planetName(b, lang)` (lib/names.ts) |
| Long-form Markdown | `westernProfile(slug, lang)` etc. return `{ fm, html, translated }`; Khmer files live at `content/km/<same path>` with the same front-matter keys. If `translated` is false on a Khmer page, show one quiet line: "អត្ថបទនេះមានជាភាសាអង់គ្លេសនៅឡើយ។" |
| Daily reading text | `blockTexts(lang)` (falls back to English per block); Khmer drafts live in `content/blocks/*.json` as `text_km` |
| Engine output that is English prose (lib/*) | add a `lang` parameter or return `{ en, km }`; never translate inside a component by string matching |

- On an English page, a Khmer word keeps `lang="km"` on its span; on a Khmer page, an English or Chinese word gets `lang="en"` / `lang="zh"`.
- Keep slugs, ids, data attributes and JSON-LD `@type` values English.

## Writing Khmer

- Plain, warm, everyday Khmer a general reader understands; second person (អ្នក). The same tone rules as English (CONTENT_GUIDELINES.md): no fear, no certainty, no health/legal/money advice, no exclamation marks.
- Sentences end with ។. Numbers in Khmer digits (០–៩). Dates written out (ទី៥ ខែតុលា ឆ្នាំ២០២៦).
- Use the names in lib/names.ts consistently (Western signs = rasi names: មេស ឧសភ …; animals = ជូត ឆ្លូវ …).
- Astrology terms: រាសី (sign), រាសីឡើង (rising sign), ភព (planet), ព្រះចន្ទ (Moon), ថ្ងៃល្អ (lucky day), ភាពត្រូវគ្នា (compatibility), ប្រតិទិនចិន (Chinese almanac), ថ្ងៃសីល (holy day).
- Every Khmer string is a DRAFT until a native reader approves it; list new files in docs/KHMER-REVIEW.md.
- Length: Khmer runs ~30–40% longer. Layouts must survive it (DESIGN_SYSTEM §8.8).
